# Session Note: April 14, 2026

## Scope
Since the previous note on March 31, we shifted from local-sigma sweeps to **global-reference validation**.

The goal was to answer one concrete question before continuing any local-sigma comparison:

- can we recover the paper-like global baselines with the correct evaluation protocol?

This matters because some of our earlier global runs diverged strongly from the papers, especially when we evaluated on feature-based linear classifiers. We wanted to separate:

- true paper-faithful references
- feature-space sanity checks
- clearly non-paper evaluation paths

## Main Decision
We concluded that the earlier comparison was mixing evaluation protocols.

Paper-faithful references are:

- **MaxHerding**: `NN1`
- **ProbCover / DCoM**: `from_images`

Feature-space sanity checks are:

- `NN1` for ProbCover
- `logistic_from_features` for both methods

The current repo `from_features` SGD path is not the paper reference. It is a generic PyTorch linear layer trained with the usual image-training stack, and it should be treated as an ablation, not as the main baseline.

## Evaluators Used

### `NN1`
This is a 1-nearest-neighbor classifier on the frozen feature embeddings.

Conceptually:

- each example is represented by a 512-d feature vector
- test prediction is the label of the closest labeled feature vector

### `logistic_from_features`
This is the evaluation mode we added to the repo.

It uses scikit-learn logistic regression on the frozen feature vectors:

- one linear score per class
- softmax-style multiclass training
- prediction by highest class score

This is a much cleaner linear-evaluation sanity check than the older SGD-trained `from_features` path.

### `from_images`
This is the paper-style downstream classifier path.

Selection still uses frozen features, but evaluation trains a ResNet-18 on labeled raw images and reports image-classification accuracy.

## Main Results

### MaxHerding
The important result is that **the paper-faithful `NN1` path looks very close to the published behavior**.

For CIFAR-10:

- final `NN1` at 100 labels: about `80.17`, `81.83`, `81.01` for seeds 0/1/2

For CIFAR-100:

- final `NN1` at 1000 labels: about `46.16`, `46.36`, `46.69`

These are the runs we currently trust as the valid MaxHerding reference.

The MaxHerding logistic results are much less aligned:

- CIFAR-10 logistic is noticeably lower and noisier than `NN1`
- CIFAR-100 logistic is much lower, and seed 0 is missing entirely in the current table

Conclusion:

- MaxHerding `NN1` behaves like the paper reference
- MaxHerding logistic does not currently behave like the paper reference

### ProbCover
The important result is that **the paper-faithful `from_images` path is the ProbCover reference that should be compared to DCoM**.

For CIFAR-10:

- `from_images` seeds 0/1/2 at 10 labels: about `20.21`, `20.93`, `19.53`
- at 50 labels: about `30.02`, `29.94`, `29.36`
- at 100 labels: about `34.44`, `33.05`, `34.49`

These are in the same low-budget regime as the DCoM table rows we can compare against.

For CIFAR-100:

- `from_images` seed 0 currently reaches about `19.16` at 1000 labels
- seeds 1 and 2 are still incomplete / missing in the combined table

The ProbCover feature-space sanity checks behave very differently:

- `NN1` is much higher than `from_images`
- logistic is also very different from `from_images`

Conclusion:

- ProbCover `from_images` is the path that looks comparable to the paper setup
- ProbCover `NN1` and logistic should be treated as alternate evaluators, not as paper references

## Paper Comparison

### What Matches the Papers
The cleanest current statement is:

- **MaxHerding + `NN1`** gives results very similar in scale and behavior to the MaxHerding paper
- **ProbCover + `from_images`** gives the right type of reference for comparison to DCoM

### What Does Not Match
The following are not matching the paper baselines and should not be treated as such:

- ProbCover + `NN1`
- ProbCover + logistic regression
- MaxHerding + logistic regression

These runs are still useful, but as sanity checks or ablations, not as the main references.

## Missing Data
There are two kinds of missing values in the current tables.

### 1. Paper rows missing
Some paper rows are blank simply because the paper does not report that budget.

Examples:

- CIFAR-10 ProbCover paper values exist for `10, 20, 30, 40, 50`, then jump to larger budgets like `200`
- so the paper column is blank for `60, 70, 80, 90, 100`

### 2. Experiment rows missing
Some seed columns are blank because those runs did not finish or did not produce the final saved curve yet.

Current important examples:

- CIFAR-100 ProbCover `from_images`: only seed 0 is currently populated
- MaxHerding logistic has partial missing values, especially seed 0 on both datasets and later rows on CIFAR-100

So blank cells in the combined tables do not all mean the same thing:

- sometimes the paper has no number for that budget
- sometimes our run is incomplete

## Interpretation
The main lesson from this validation pass is:

- the evaluation protocol matters much more than we hoped
- when we use the paper-faithful evaluator, the reference makes sense
- when we change the evaluator, the numbers can move a lot

This is especially important before returning to local sigma.

We should compare local sigma only against a reference that is already validated under the correct evaluation protocol:

- MaxHerding local sigma vs MaxHerding global `NN1`
- ProbCover local sigma vs ProbCover global `from_images`

## Practical Conclusion
Before continuing local-sigma comparisons, our valid anchors are:

- MaxHerding global sigma with `NN1`
- ProbCover global sigma with `from_images`

Feature-space evaluators remain useful for diagnostics, but they should not be mixed into paper-reproduction claims.
