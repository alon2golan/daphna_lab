## Main Results

### CIFAR-10, `from_features`
- global sigma final: `27.70`
- best local sigma final: `55.72` at `K=20000`
- improvement over global: about `+28.02`

This is a very large gap. In this setup, local sigma is not a tiny effect around the global baseline. It changes behavior dramatically.

### CIFAR-10, `from_images`
- global sigma final: `25.12`
- best local sigma final: `33.29` at `K=2000`
- improvement over global: about `+8.17`

This is much smaller than the feature-based gain, but still clearly meaningful.

### CIFAR-100, `from_features`

- improvement over global: about `+2.05`

This is a moderate but clear gain.

### CIFAR-100, `from_images`
- global sigma final: `21.70`
- best local sigma final: `29.13` at `K=60`
- improvement over global: about `+7.43`

This is a large improvement in the paper-style image-evaluation path.

## Comparison to the Paper

We specifically checked whether the CIFAR-10 image-trained global ProbCover reference looked inconsistent with the DCoM table.

Relevant run:

- [probcover_cifar10_seed2_images_global_ref-29705435.txt](/cs/labs/daphna/ido.dotan/projects/daphna_lab/outputs/probcover/low_budget_k_sweep/cifar10/images/global_sigma/probcover_cifar10_seed2_images_global_ref-29705435.txt)

At first glance it looked far too low because the final accuracy at `100` labels is only about `25.12`, while the paper table later reaches `90+`.

The key clarification is that the DCoM CIFAR-10 table in [DCOM.txt](/cs/labs/daphna/ido.dotan/projects/daphna_lab/DCOM.txt) uses labeled-set sizes:

- `10, 20, 30, 40, 50, 200, 400, 600, 800, 1400, 2600, 3800, 5000, 6200, 7400`

So the `90+` values are for much larger budgets. The correct overlap is only at:

- `10`
- `20`
- `30`
- `40`
- `50`

At those overlapping budgets, the current image-trained CIFAR-10 global run is actually in the same scale and slightly above the table values:

- paper `10`: `12.62`, ours `13.77`
- paper `20`: `13.30`, ours `17.96`
- paper `30`: `13.91`, ours `17.14`
- paper `40`: `14.32`, ours `18.30`
- paper `50`: `15.09`, ours `18.91`

So the corrected conclusion is:

- the current CIFAR-10 image-trained global run does **not** contradict the paper at the overlapping low-budget rows
- the apparent mismatch came from comparing a `100`-label experiment to much larger-budget table rows

## What We Expected

Before running ProbCover local sigma, the main expectation was:

- small `K` would likely be bad
- very large `K` would make local sigma look more like global sigma
- if local sigma only worked at very large `K`, then the same “near-global smoothing” interpretation from MaxHerding would likely apply

We also expected ProbCover to be more sensitive than MaxHerding because its tophat graph is based on hard thresholds, so changing local scale changes the graph structure discretely rather than just reweighting a smooth kernel.

## What Surprised Us

### 1. ProbCover Benefits Much More From Local Sigma Than MaxHerding
The size of the gains is the main surprise.

In MaxHerding, large `K` usually only made local sigma competitive with global sigma, and the gains were small.

In ProbCover, local sigma produced much larger improvements:

- especially on CIFAR-10 `from_features`
- and also noticeably on both image-trained runs

So ProbCover is qualitatively more responsive to local sigma than MaxHerding.

### 2. The Best `K` Is Not Always Huge
For image-trained ProbCover:

- CIFAR-10 best `K` was `2000`
- CIFAR-100 best `K` was `60`

So again, bigger is not always better. There seems to be an optimal range.

### 3. Paper Alignment Required a Budget Interpretation Fix
We initially thought the image-trained CIFAR-10 global reference was failing badly relative to the DCoM table.

After checking the actual labeled-set sizes in the table, we found the comparison had been made against the wrong budget rows.

## Interpretation

### Sigma Statistics Still Show the Same Structural Trend
As `K` increases:

- mean sigma increases
- median sigma increases
- `cv` decreases
- `iqr` decreases

So the sigma field becomes smoother and less relatively variable, just like in MaxHerding.

### But ProbCover Responds Differently
Despite that smoothing trend, ProbCover does **not** look like a case where local sigma only works when it becomes nearly global.

Why:

- the gains over global are much larger
- moderate `K` values can already outperform global substantially
- the best image-trained CIFAR-100 result happens at `K=60`, which is not in the most global-like regime

That suggests a different interpretation from MaxHerding:

- for ProbCover, local sigma may be doing something genuinely useful to the coverage graph
- it may be correcting the effective neighborhood radius in a way that helps the hard-threshold graph reflect density better

In other words:

- in MaxHerding, local sigma mostly looked like a mild smoothed perturbation of global sigma
- in ProbCover, local sigma looks more capable of changing the actual selection behavior in a beneficial way

### One Likely Intuition
ProbCover depends directly on who is inside whose coverage ball.

With one global delta:

- dense regions can become over-connected
- sparse regions can become under-covered
- a single radius may be a poor compromise

With local sigma:

- dense points can use smaller effective radii
- sparse points can use larger effective radii
- the resulting graph can better balance coverage across heterogeneous density regions

This kind of effect should matter more for a hard-threshold graph than for a smooth RBF kernel, which is consistent with what we observed.

## Current Takeaways

1. For ProbCover, local sigma looks significantly more promising than it did for MaxHerding.
2. The effect is present in both `from_features` and `from_images`, so it is not limited to one evaluator.
3. The CIFAR-10 image-trained global reference is not inconsistent with the paper once the budget rows are matched correctly.
4. The best `K` is not necessarily the largest one.
5. The results suggest that local adaptation may matter more for ProbCover’s hard-threshold graph than for MaxHerding’s smooth kernel.

## Caveats

1. These are still mainly seed-2 results.
2. Some ProbCover tables have fewer rows than the full `13 + global`, so not every intended `K` was recovered into the CSVs.
3. The normalized ProbCover comparison has not been run yet, so we still do not know how much of the effect depends on using unnormalized features.
4. The feature-based ProbCover path is useful as an ablation, but the paper-faithful comparison is the image-trained path.

## Likely Next Questions

- Does the local-sigma gain for ProbCover reproduce across more seeds?
- How much of the effect remains when features are normalized?
- Is the gain strongest at moderate `K` because it balances adaptivity with graph stability?
- Can we characterize the graph directly, e.g. average degree / coverage distribution, to explain why local sigma helps more in ProbCover than in MaxHerding?
