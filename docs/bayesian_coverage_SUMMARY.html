Bayesian Coverage — How It Works + Results vs. Netta's NPC/AUM

2026-07-08

Branch: bayesian_coverage (HEAD 236cf81) Companion docs: design spec in docs/bayesian_coverage_DESIGN.md; implementation in deep_al/pycls/al/bayesian_coverage.py; training wiring in deep_al/tools/train_al.py (_bayes_training_loader) + deep_al/pycls/noise/noisy_label_wrapper.py. Everything in this file is verified against the code and the actual result.json files on disk.

0. TL;DR

We work with noisy annotators and act on two planes:

  1. Point selection (AL): replace ProbCover’s binary covered/not-covered with a per-class posterior distribution per point, built from neighbor annotations, each weighted by its annotator’s confusion matrix and its kernel distance, fused as a product of experts. Select the point whose ball contains the most remaining uncertainty mass.
  2. Training: reuse the same posterior to build the training targets — six configurable policies (TRAIN_LABEL_MODE), from raw noisy labels to full soft labels to curriculum pseudo-labeling of unlabeled points (pseudo, §4.6).

Headline result (CIFAR100): the selection plane alone \approx ProbCover; the training plane is where the method pays. At noise 0.5/0.8, training on the posterior (soft_posterior / map_posterior) beats both raw-label training (2.2\times at noise 0.8) and Netta’s NPC+AUM. The §7.5 pseudo-labeling arm (§4.6) then beats every other arm at every noise level including clean (e.g. 47.8 vs 45.1 observed at noise 0 @1000; 45.8 vs NPC+AUM’s 43.3 at noise 0.2) — closing the one regime where Netta’s stack had led.

1. The probabilistic model (selection plane)

Class: BayesianCoverage(CoverageMatrixMethod) — a new subclass; the base ProbCover/NPC path is byte-untouched.

Every pool point u carries a distribution P(y_u = k) over all classes instead of a covered bit. It is built in three steps:

Step A — annotator noise enters (_belief, bayesian_coverage.py:171)

For a labeled point \ell with observed label \tilde{y}_\ell from annotator a, the belief over its own true label is Bayes’ rule through the annotator’s confusion matrix M^a[k,j] = P(\text{observed } j \mid \text{true } k):

b_\ell(k) \;\propto\; \pi(k)\cdot M^a[k,\, \tilde{y}_\ell]

  • \pi = the class prior (uniform, 1/C). Terminology note: the prior is \pi, not the annotator-confidence vector — b_\ell is already a (Step-A) posterior on \ell’s own label.
  • Symmetric annotator with accuracy \rho:

b_\ell(k) = \begin{cases} \rho & k = \tilde{y}_\ell \\[2pt] \dfrac{1-\rho}{C-1} & k \neq \tilde{y}_\ell \end{cases}

E.g. a 50%-noise annotator on CIFAR100: 0.5 on the observed class, 0.5/99 elsewhere. - The full confusion matrix is used, so asymmetric annotators work for free (commit 9b54ce0; Annotator.confusion_matrix).

Step B — geometry enters (_neighbor_loglik, line 189)

The belief propagates to any other point u through the kernel edge, diluted by distance:

q_\ell(u,k) \;=\; K[u,\ell]\cdot b_\ell(k) \;+\; \bigl(1-K[u,\ell]\bigr)\cdot \pi(k)

How to read q_\ell(u,k). It answers: “given only what neighbor \ell knows, how likely is it that point u belongs to class k?” — one neighbor’s “message” about u, a full distribution over the C classes (one q_\ell(u,\cdot) vector per (neighbor, point) pair). It is a mixture of two hypotheses, weighted by the kernel:

  • With probability K[u,\ell]: “u and \ell share the same true label” (the ProbCover ball assumption holds) — then everything we believe about \ell’s label, b_\ell, transfers to u as-is.
  • With probability 1-K[u,\ell]: “u is unrelated to \ell” — then \ell tells us nothing about u, and the message falls back to the prior \pi.

Limit cases, with a 60%-accurate annotator on CIFAR100 that said class 7:

Situation K[u,\ell] q_\ell(u,\cdot)
u right next to \ell 1 = b_\ell: 0.6 on class 7, 0.4/99 elsewhere
u far from \ell 0 = \pi: uniform 1/100 — no information
smooth kernel, mid-distance 0.5 halfway: 0.303 on class 7, ~0.007 elsewhere

Close neighbor + accurate annotator \Rightarrow peaked toward \tilde{y}_\ell. Far neighbor or noisy annotator \Rightarrow flat toward the prior. With the tophat kernel (what all our runs use), K \in \{0,1\} — inside/outside the \delta-ball — so distance acts as a gate: in-ball neighbors send b_\ell, out-of-ball neighbors send the (information-free) prior.

Step C — fuse all labeled neighbors (product of experts)

All labeled neighbors are combined in log-space (naive Bayes over neighbors):

C[u] \;=\; \log \pi \;+\; \sum_{\ell \in L} \beta\, w_{u\ell}\, \log q_\ell(u,\cdot), \qquad P(y_u = \cdot) \;=\; \operatorname{softmax}\bigl(C[u]\bigr)

Equivalently in probability space — each neighbor’s message enters as a fractional vote with exponent \beta\, w_{u\ell}:

P(y_u = k) \;\propto\; \pi(k)\, \prod_{\ell \in L} q_\ell(u,k)^{\,\beta\, w_{u\ell}}

(In the code, _neighbor_loglik returns exactly temper_beta * w * log q, accumulated into self.C by _fold_neighbor.)

  • Product, not addition: agreeing neighbors sharpen the posterior; a single confident-but-wrong neighbor is overridable. The additive rule (C[:,\text{label}] \mathrel{+}= K_{\text{row}} — Itai David’s BAYES_MISP) is kept behind COMBINE=additive as the empirical control (design §3 demanded the comparison, not an assumption). Result: product wins decisively (see §5.4).

1.4 The weights w_{u\ell} and the temper \beta — correlated-neighbor overconfidence

The product above is naive Bayes: it assumes every labeled neighbor is an independent piece of evidence. Neighbors that are close to each other violate this — they describe the same local patch, so their labels are near-duplicates of one measurement, and a raw product counts the same information several times over.

Worked example (2 classes): five clustered neighbors, each giving u a message that is 0.7-confident for class A.

  • Naive product (\beta = 1, full votes): odds = (0.7/0.3)^5 \approx 69{:}1 \Rightarrow P(A) \approx 0.99.
  • But if the five points are effectively one measurement, the honest belief is \approx 0.7. The raw product is badly overconfident.

Overconfidence hurts both planes: an overconfident posterior looks “covered”, so the acquisition score stops sampling that region; and soft_posterior training targets inherit the false peak.

Two knobs shrink the per-neighbor exponent (design §2.4):

  1. Kernel weighting — NEIGHBOR_WEIGHT='kernel' (default): w_{u\ell} = K[u,\ell]. Each message is scaled by its relevance to u: a neighbor on top of u casts a full vote, a marginal one a fraction. Caveat for our runs: with the tophat kernel K \in \{0,1\}, so this degenerates to a gate — every in-ball neighbor still casts a full vote. It only becomes a real gradient with a smooth kernel (e.g. RBF).
  2. Tempering — TEMPER_BETA = \beta < 1: multiply every message uniformly, i.e. raise every likelihood to the power \beta (“fractional Bayes”). With N agreeing neighbors the effective evidence count becomes \beta N instead of N: in the example, \beta = 0.2 turns (0.7/0.3)^5 back into (0.7/0.3)^1 = 0.7.

The two are complementary and multiply: w_{u\ell} discounts per neighbor by relevance (“this neighbor is far”), \beta discounts all neighbors uniformly (“I distrust the independence assumption as such”).

“Isn’t distance already inside q_\ell — why multiply by \beta w again?” Legitimate question; three-part answer.

  1. The exponent is not needed for correctness. With a uniform prior, q_\ell(u,k) is exactly the naive-Bayes likelihood P(\tilde{y}_\ell \mid y_u = k) up to a class-independent constant (marginalize over “do u,\ell share a label?”: w.p. K the likelihood is M^a[k,\tilde{y}_\ell], w.p. 1-K it is constant in k). So the exact Bayesian fusion is the plain product: exponent 1, i.e. w=equal, \beta=1.

  2. But the two factors do different jobs. Inside-K sets the content of one message (how peaked); the exponent sets its evidence count (how many votes). Dilution alone cannot bound accumulation: N correlated neighbors each sending a mild message still accumulate N\log q, and as N grows the softmax converges to a one-hot — any slightly-peaked message, repeated, multiplies into (false) certainty. Only an exponent <1 slows the accumulation itself.

  3. Using w=K as that exponent is a heuristic, and it does double-count distance under a smooth kernel (a K=0.5 neighbor is diluted and half-weighted). It is §2.4’s cheap proxy — and note it doesn’t even measure what causes the correlation (neighbor-to-neighbor closeness, not distance to u). The principled knob is the uniform \beta (standard power/fractional-posterior practice). For smooth-kernel runs, NEIGHBOR_WEIGHT=equal + tuned \beta is the cleaner configuration.

    With tophat this is all moot: K\in\{0,1\} makes the exponent exactly 1 in-ball, and an out-of-ball neighbor contributes nothing under either weighting (its q=\pi is class-constant and cancels in the softmax) — so the experiments in §4 ran the exact naive-Bayes rule, with no double counting.

Status in the experiments below: defaults are \beta = 1.0 (tempering off) and tophat kernel (weights degenerate to 1 in-ball) — so all results in §4 were obtained with the raw, untempered product. The design-§10 check “overconfidence controlled by TEMPER_BETA / NEIGHBOR_WEIGHT” is still unverified; a cheap \beta-sweep (\beta \in \{0.25, 0.5, 1.0\}) is an open follow-up and might specifically help soft_posterior at high noise, where posterior sharpness directly shapes the training targets.

Selection criterion — what “maximizing the updated cover” means

Coverage is now graded: a point is well-covered when its posterior is peaked, uncovered when flat. The acquisition score (_acquisition_scores, line 211):

\text{uncertainty}(u) \;=\; 1 - \max_k P(y_u = k)

\text{score}(v) \;=\; \sum_u K[v,u]\cdot \text{uncertainty}(u) \qquad \text{(unresolved mass inside } v\text{'s ball)}

Greedy loop picks \arg\max_v \text{score}(v) — the soft generalization of ProbCover’s “ball covering the most uncovered points”. Two load-bearing mechanics:

  • Annotation is in-loop (_select_one, line 250): each pick is annotated immediately and folded into C, so the next pick already sees the updated posteriors.
  • Noise-awareness for free: a label from a noisy annotator barely sharpens its ball’s posteriors, so the region stays attractive for re-sampling — the method knows one noisy label didn’t really cover it.
  • Cross-episode: C resets to the prior each AL episode, then the whole labeled set is re-folded from annotation records (_fold_labeled_set, line 124); without this, prior episodes’ evidence would be lost and episode 2+ would re-sample regions episode 1 already labeled (their neighbors would look uncovered again). Note — this is an engineering choice, not part of the algorithm: the posterior is in fact persisted (C_general, global-indexed — training reads it from there), but the per-episode C is locally indexed and the index order changes as the labeled set grows, so rebuilding is simpler than remapping. Replaying costs one vector-add per labeled point (milliseconds) and is correct by construction: the posterior is a pure function of the recorded (label, annotator) pairs.

Still NotImplementedError: entropy (BALD-style) acquisition, empirical prior, sparse-K, NoiseAwareBayesianCoverage (soft per-point reliability r_\ell, design §4).

2. Training plane — TRAIN_LABEL_MODE (design §5, commit 61e7557)

After selection, the same posterior builds the training targets. Wired in train_al.py::_bayes_training_loader (line 744); soft modes go through SoftTargetDatasetWrapper + a soft-cross-entropy branch. Five arms, all swept:

Mode Classifier trains on Loss path
observed raw annotated (noisy) labels — baseline standard CE
map_posterior each labeled point relabeled to argmax of its posterior (self-correction) standard CE
filtered only points whose neighbors agree with their annotation standard CE, subset
soft_posterior the full posterior vector as a soft label soft CE
reweighted one-hot on observed label, scaled by reliability w soft CE (weight = row sum)

“Loss path” = which cross-entropy (CE) branch the mode takes in the training loop (train_al.py:1044) — it is the loss:

  • standard CE: the usual hard cross-entropy against an integer class label — equivalently a one-hot target vector.
  • soft CE: the target is a full probability vector t \in [0,1]^C (e.g. the posterior, sums to 1), and the loss is -\sum_k t_k \log \operatorname{softmax}(z)_k. Mechanically: soft modes ship a 2-D float label batch [B, C], and the loop switches on labels.dim() == 2.
  • reweighted twist: its target row is w_\ell \times one-hot, which sums to w_\ell, not 1 — running it through the same soft-CE formula automatically scales that sample’s loss by w_\ell, so the row sum doubles as the per-sample weight (no separate weighting code).

filtered in detail (common misreading — it is not a threshold on the posterior value): it computes the leave-one-out (LOO) posterior P^{\text{LOO}}_\ell — the point’s posterior with its own vote removed (_loo_posterior_for, line 295). Necessary because the self-vote (K[\ell,\ell]=1) dominates and a point would almost never disagree with itself.

\text{keep } \ell \iff \arg\max_k P^{\text{LOO}}_\ell(k) \;=\; \tilde{y}_\ell

Your neighbors, judging you without your input, agree with the annotator. reweighted uses the same signal continuously:

w_\ell \;=\; P^{\text{LOO}}_\ell\bigl(\tilde{y}_\ell\bigr)

— suspect points are down-weighted, not dropped.

Key design point: the clean/dirty signal is the graph posterior itself (design §4b) — no trained model, no AUM, available from round one, and non-circular (AUM judges labels with a network trained on those same labels).

3. The comparison baseline — Netta’s NPC + AUM

Same problem, two hard mechanisms (noise_filters.py, NoiseAwareCoverage in coverage_matrix_methods.py):

  • AUM filter (training plane). AUM = Area Under the Margin: while training on the noisy labeled set, accumulate per-sample over epochs the margin between the assigned-label logit and the largest other logit:

\text{AUM}(x,\tilde{y}) \;=\; \frac{1}{T}\sum_{t=1}^{T} \Bigl( z^{(t)}_{\tilde{y}}(x) \;-\; \max_{k \neq \tilde{y}} z^{(t)}_{k}(x) \Bigr)

Symbols: x = one training sample; \tilde{y} = its assigned (possibly noisy) label; t = training-epoch index, T = number of epochs measured over; z^{(t)}_k(x) = the network’s logit (pre-softmax score) for class k on sample x at epoch t. So z^{(t)}_{\tilde{y}}(x) is the score of the label the sample was given, \max_{k \neq \tilde{y}} z^{(t)}_k(x) is the score of the strongest competing class, and their difference is the margin at epoch t (positive = the network currently agrees with the assigned label). AUM is that margin averaged over the whole training run — the “area under” the margin-vs-epoch curve. Mislabeled samples fight the network \Rightarrow low/negative AUM. Threshold \Rightarrow binary clean/noisy mask \Rightarrow train only on the clean subset (TRAIN_ON_CLEAN). - NPC (selection plane). ProbCover, except coverage contributed by points flagged noisy is removed — a noisy point’s ball no longer counts as covered, so the region gets re-sampled.

Relationship: NPC is exactly the limiting case of Bayesian coverage with reliability hard-thresholded to r_\ell \in \{0,1\} (design §4) — delete vs. down-weight, and AUM-as-judge vs. graph-as-judge.

4.5 The posterior itself, measured directly (offline replay — no classifier)

The posterior is a pure function of (features, labeled ids, annotation records), so it can be rebuilt offline and scored against ground truth with no classifier in the loop. The denoising crossover, isolated. At noise ≥ 0.5 the posterior argmax is a far better label than the annotation (61.6% vs 20.6% at 0.8 — 3× cleaner; 67.7 vs 49.5 at 0.5): the §4 training-plane wins traced to their source. At noise ≤ 0.2 it is worse (66.2 vs 81.0 at 0.2; 68.3 vs 100 clean). The mechanism is δ-ball impurity: in-ball neighbors of other classes outvote the point’s own annotation — on perfectly clean data, 31.7% of labeled points sit in balls whose neighbor-vote prefers another class, so ~32% is the measured impurity of the “same ball ⇒ same label” assumption on CIFAR100 SimCLR features at δ=0.75. This is the root cause of takeaway 5 (correction costs on clean data) and of NPC+AUM’s remaining edge at noise 0.2. Curious tension: at 0.2, map_posterior matches observed in test accuracy (§4) despite training on 15-points-worse labels — the wrong relabels agree with the feature geometry, so they are consistent targets; raw label accuracy understates a target’s usefulness.

Flag recall is ~99% at noise ≥ 0.5 (nearly every truly-noisy label gets flagged). Three sharp conclusions:

  1. The score is good, the threshold is broken. As a ranking, LOO reliability detects noisy labels well (AUC 0.86–0.92 from 300 labels on). But the filtered keep-rule (“LOO argmax == observed”) flags 53% of perfectly clean labels at noise 0 — ball impurity makes neighbor-argmax a hopeless bar. filtered/ reweighted fail because of the threshold, not the signal (sharpens 7.6: use a percentile / calibrated cut on the continuous w_\ell, not argmax agreement).
  2. The naive 7.1 gate signal saturates. The LOO-disagreement fraction cannot tell clean from 20%-noise (52.9 vs 52.6) — the ~53% impurity floor swamps it. The noise-gate needs the continuous w_\ell distribution or an impurity-corrected baseline, not the raw disagree fraction.
  3. Budget-100 LOO verdicts are numerically arbitrary. Most labeled points have no other labeled neighbor in-ball at 100 labels; their LOO posterior is uniform and the keep/drop decision comes down to float32 rounding residues (reproducing the runs’ exact counts required replicating summation order). The filtered@100 collapse in §4 is exactly this.

5. Takeaways

  1. Selection plane alone ≈ ProbCover. bayes_product wins small at the very-low end (1/class: 21.6 vs 19.7 @noise .2; 14.9 vs 13.1 @.5), converges or trails slightly by 1000 labels. Annotator-accuracy weighting matters most when labels are scarcest, but selection alone is not the win.
  2. The training plane is the win — and it beats Netta’s AUM at noise ≥ 0.5. Noise 0.8 @1000: soft_posterior 27.5 vs observed 12.6 (2.2\times) vs NPC+AUM 15.0. Noise 0.5 @1000: 39.1 vs 29.5 vs 35.6. Soft graph-posterior label correction dominates hard AUM filtering exactly where noise is heaviest — plausibly because AUM’s judge network was itself trained on 50–80% wrong labels, while the graph posterior needs no trained model.
  3. At noise 0.2, NPC+AUM still slightly ahead (43.3 vs 41.5 @1000). Few flips ⇒ AUM is reliable, and hard-dropping a few bad points beats softening every label.
  4. Product ≫ additive at every cell — design-§3 gate passes decisively; additive collapses on CIFAR100 (26.9 vs 45.1 clean @1000). ⚠ Caveat: at noise 0 on CIFAR100 the additive arm also fails the “reproduces Itai ≈ probcover” sanity check (13.4 vs 23.6 @100; it passed on CIFAR10) — so on CIFAR100 our additive branch is not a faithful Itai control (likely the Dirichlet(\pi) init vs. his scalar-\alpha; open item).
  5. Clean-data sanity holds: at noise 0, observed is best; every correction mode costs a little (soft 42.5 vs 45.1). Correcting labels that aren’t wrong removes signal ⇒ the mode should be noise-gated: observed when clean, soft/map when noisy.
  6. filtered/reweighted collapse at budget 100 (~5% even at noise 0): with ~1 label/class the LOO posterior has almost no neighbors to judge with, so it drops/down-weights good points. Respectable only from ~500 on ⇒ needs a minimum-neighbor gate if kept.
  7. Trust checks: NPC ≡ PC at episode 1 in Netta’s sweep (filtering starts after the first training round); AUM-ablation clean=off arms reproduce the no-filter baselines bit-for-bit (deterministic pipeline).
  8. Pseudo-labeling (§4.6) is the new best training arm at every noise level — and it removes the noise gate’s necessity. It beats the previous per-noise winners at 1000 labels: 47.8 vs 45.1 (observed) clean, 45.8 vs 41.5 (soft) at .2, 41.8 vs 39.1 at .5, 29.0 vs 27.5 at .8 — and, unlike soft/map, it also beats NPC+AUM at noise 0.2 (45.8 vs 43.3), so the method now leads Netta’s stack everywhere. Within the arm: all dominates at low budget (37.6 vs 26.3 @100 clean — coverage volume matters most when labels are scarcest) and stays best through noise .5; the curriculum arms catch up by 1000 and agg50 is the safer choice at noise .8 (29.0 vs 28.1), consistent with guard (b) being unimplemented — all amplifies noisy balls hardest exactly where labels are least reliable. Takeaway 5’s clean-data penalty does not apply: pseudo helps clean data too, so pseudo needs no noise gate (only the scope choice might be gated).

7. Next steps

Ordered roughly by value; items 1–3 follow directly from the §5 takeaways.

7.1 Noise-gated training policy

The sweep showed a clean trade-off: under noise, posterior-based training wins big (+15 pts at noise 0.8 @1000), but on clean data it costs ~2–3 pts — correcting labels that aren’t wrong throws away signal (takeaway 5). So the right production policy isn’t “always soft_posterior,” it’s a switch. The open question is how the method knows it’s in a noisy regime without being told. Candidate gate: for each labeled point we already compute the LOO posterior (its neighbors’ verdict without its own vote, §2); the fraction of points where that verdict disagrees with the annotation is essentially a free noise-rate estimate — no trained model needed. Clean data → few disagreements → stay on observed; noisy → many → switch to soft/map. ⚠ Measured (§4.5 D): the raw disagree fraction saturates at a ~53% ball-impurity floor and cannot distinguish noise 0 from 0.2 (52.9 vs 52.6) — the gate must use the continuous w_\ell distribution or an impurity-corrected baseline instead. Work items: design that corrected statistic (calibrate against §4.5’s replay across 0/.2/.5/.8), then wire as TRAIN_LABEL_MODE=auto.

7.2 Writeup plot + more seeds

The headline claim (soft_posterior 27.5 vs observed 12.6 at noise 0.8) currently rests on 3 seeds with ±2–3 pt stds at mid-budgets — fine for a direction, thin for a figure someone will scrutinize. Concretely: a gain plot (soft_posterior − observed, per budget per noise) with error bars, plus ~3 extra seeds at the cells where the std is widest (noise 0.8, 300–500 labels). Cheap: a re-run of existing configs with new seeds, ~15 GPU-runs.

7.3 Head-to-head clean-signal comparison (judge vs judge)

The Bayes-vs-Netta comparison currently confounds two differences at once: selection rule (bayes_product vs npc) and clean-signal (graph posterior vs AUM). The §4 decomposition note showed selection barely matters for either method — so the interesting fight is judge-vs-judge, and the current tables never stage it directly. The 2×2 to fill in: {bayes_product, npc} × {posterior-based training, AUM clean-train}. The two missing cells: bayes_product + AUM clean-train (mostly config wiring — NOISE_FILTER=aum on a bayes run) and npc + soft_posterior (needs the posterior computed on an npc run; slightly more plumbing). If graph-judge wins even on npc selection, the story is clean: the posterior is a better label-quality judge than AUM, independent of selection.

7.4 \beta-temper sweep

All results so far use the raw untempered product (\beta = 1), which naive-Bayes-overcounts correlated neighbors (§1.4): five clustered neighbors saying “class A at 0.7” multiply into ~0.99 certainty when the honest belief is ~0.7. This false sharpness feeds directly into soft_posterior training targets (over-peaked = closer to a possibly-wrong one-hot) and into selection (overconfident regions stop being sampled). Now confirmed empirically (§4.5 C): the posterior is overconfident at every noise level (ECE 0.10–0.29, confidence > accuracy everywhere, worst on clean data). A \beta \in \{0.25, 0.5, 1.0\} sweep on bayes_product + soft_posterior at noise .5/.8 is ~36 runs — and §4.5’s offline replay gives a shortcut: pre-tune \beta by minimizing ECE offline, then confirm the winner with a small training sweep. Expectation: \beta < 1 helps most exactly where the headline result lives.

7.5 Semi-supervised training arm (pseudo-labeling) — ✅ DONE (2026-07-09)

Implemented as TRAIN_LABEL_MODE='pseudo' (+ PSEUDO_SCOPE/PSEUDO_K_SCHEDULE, CLI --pseudo_scope/--pseudo_k; launcher batch_utils/sweep_bayes_pseudo.py) and swept as job 31047129 — results in §4.6, takeaway 8: best training arm at every noise level, no noise gate needed. Guard (a) (exclude prior-only points) is implemented — a prior-only point has a flat accumulator row and is never harvested. Guard (b) (cap correlated evidence per ball) is still open: one noisy annotation can be amplified into dozens of agreeing pseudo-targets (the §1.4 double-counting problem moved to the training plane). The results show its fingerprint — all trails the slow-curriculum agg50 only at noise .8 / high budget (28.1 vs 29.0) — so a per-ball cap is the natural next refinement if the high-noise cells matter for the writeup. Remaining follow-ups: per-ball caps, a confidence floor for all (harvest only above a posterior-max threshold), and scope gating (all→topk as noise grows).

7.6 Fix filtered/reweighted at low budget

Both modes collapse to ~5% at budget 100 even on clean data (takeaway 6): with ~1 label/class, a point’s LOO posterior is built from almost no neighbors, so the “judge” fires on noise and drops/down-weights good points — §4.5 D showed the budget-100 verdicts are literally decided by float rounding (no in-ball neighbors → uniform LOO). §4.5 D also relocated the real defect: the LOO score ranks noisy labels well (AUC 0.86–0.92), but the “argmax == observed” threshold flags 53% of clean labels. Fix accordingly: (a) minimum-neighbor gate (fall back to observed below N in-ball neighbors), and (b) replace the argmax rule with a percentile / calibrated cut on the continuous w_\ell. Worth doing only if these modes stay in the story; if soft/map remain the winners, this becomes documentation rather than code.

7.7 Additive-arm fidelity (Itai control)

On CIFAR100 our additive branch scores 13.4 @100 clean vs probcover’s 23.6 — it fails the “reproduces Itai ≈ probcover” sanity check that it passed on CIFAR10 (takeaway 4). So the CIFAR100 “product ≫ additive” margin, while surely real in direction, is measured against a possibly-unfaithful Itai control. Suspected cause: our Dirichlet(\pi) row-init vs his scalar-\alpha pseudocount (different effective prior strength as counts accumulate). Fix: expose \alpha as a config knob, match his value, re-run the additive arm only (12 runs). Matters mainly if the writeup cites the additive comparison as an Itai reproduction.

7.8 Remaining NotImplementedError stubs

In rough order of interest:

  • entropy acquisition (BALD-style): select by posterior entropy in the ball rather than 1-\max — could differ where the posterior is multi-modal.
  • NoiseAwareBayesianCoverage (design §4): per-point soft reliability r_\ell — the theoretical umbrella under which NPC is the hard r_\ell \in \{0,1\} limit; nice for the paper’s framing.
  • Empirical prior: \pi from observed label frequencies instead of uniform — only matters off CIFAR’s balanced classes.
  • Sparse-K: memory scaling for bigger pools — pure engineering; blocks ImageNet-scale runs, nothing else.
